# 按架构分包与 App 内更新 Implementation Plan

> 执行：使用 executing-plans，本人顺序实现；用户要求不使用子代理、不提交、不推送。保留当前工作区所有未提交修改。

**Goal:** Android 按 CPU 架构选包，App 弹窗和系统通知显示下载进度，后台持续下载，核验后由用户点击覆盖安装。

**Architecture:** GitHub Releases 保留现有来源；选择设备匹配的 APK，兼容旧通用包。原生 DownloadManager 持有下载，独立偏好记录任务；下载完成后将核验过的包保存到私有目录，以受限 FileProvider 交给系统安装器。Flutter 只查询任务并呈现主题弹窗，不拥有下载进程。

**Tech Stack:** Flutter MethodChannel / ChangeNotifier / ThemedDialog；Android DownloadManager、BroadcastReceiver、PackageManager、FileProvider；现有 GitHub Actions。

**Spec:** 用户本轮及此前已确认的方案：按架构缩小安装包，保留功能；进度弹窗可收起并后台下载，通知栏随下载刷新；Gitee 尚未建好，不虚构地址也不创建远程仓库；GitHub 可用；仅做必要验证，不提交。

## 约束与检查

- [x] 资产选择测试：优先设备 ABI；只有明确的通用包可回退；不选择其他架构或非本仓库文件；兼容旧发布。
- [x] 下载/安装策略测试：HTTPS 本仓库来源、包名、签名、递增版本、大小/哈希检查；错误包不打开安装器。
- [x] 原生下载独立于 Flutter 生命周期，任务可恢复、去重、取消、失败重试；完成通知回到进度弹窗。
- [x] 主题弹窗、设置进度入口、安装授权返回流程；非 Android 保留发布页入口。
- [x] 发布三种 ABI 的 APK 与 SHA256 清单，统一基础 versionCode，避免架构偏移阻碍后续升级。本地版本升级到 1.2.0+6，保持原签名。
- [x] 必要 Dart/JVM 测试、分析和分包构建；检查实际大小、ABI、签名和 versionCode。
- [x] 专用 Android 测试设备验证下载弹窗、后台及通知进度、进程退出、点击安装与原数据保留。合成更新源仅放在独立测试副本中，正式构建不含测试源；恢复设备并保存证据。

## 重点边界

1. 两次点击只保留一个下载任务；关闭弹窗不会取消下载。
2. 网络暂停、没有 Content-Length、任务被系统移除都要有可恢复反馈。
3. 截断、哈希不符、错误包名/签名、旧版本均禁止安装；验证不触及业务数据。
4. 完成通知和 Activity 重建后恢复同一任务；初次安装来源授权后继续用户已请求的安装。
5. 旧通用版用户升级到 ABI 版，之后仍可按基础递增版本正常升级。

## 实施与验证结果

- 版本 1.2.0+6；三种 ABI 同为 versionCode 6、保持原发布签名。ARM64 43.44 MiB、ARM32 38.06 MiB、x86_64 45.13 MiB。中文识别模型均保留。
- 发布流程先上传旧客户端需要的通用兼容包，再挂分包；新客户端按设备 ABI 优先选择。Gitee 暂不接入。
- DownloadManager 在后台/进程退出后继续；校验到私有缓存后通知，用户点按才安装，支持未知来源授权返回继续。
- 实测发现 DownloadProvider 不同 UID 的完成广播被非导出接收器挡住，已修正为导出但严格核对本应用的下载任务 ID；下载通知点击只打开进度。
- 仅将新增更新包缓存和下载任务元数据排除在系统备份及设备迁移之外，原业务数据备份范围保持不变。
- 15 项 Dart 测试、3 项 JVM 策略测试通过；Flutter 分析无问题；四个签名产物构建、ABI、模型、versionCode/cert 检查通过。
- 专用 Android API 36 x86_64 模拟器：后台下载进度、结束 App 进程后系统继续并发完成通知、通知打开已校验包、首次安装来源授权、系统覆盖安装均走通。Google Play Protect 首次侧载确认由系统显示；未关闭设备安全设置、未上传 APK 扫描。
- 从通用 1.1.1+5，经隔离测试源的同版本更新器，实际覆盖安装正式分包 1.2.0+6。升级前后 6 作业、6 课表及其余导出字段逐项一致（仅 exportedAt 不同）；桌面数量仍为 3、作业点击跳转正确。
- 完成验证后安装正式最终产物，复核 APK 哈希与业务数据；测试源不在正式代码中。记录位于 ../audit-artifacts/20261020-updater/。未提交、推送或发布。
